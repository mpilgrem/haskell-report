\haddockmoduleheading{Data.Int}
\label{module:Data.Int}
\haddockbeginheader
{\haddockverb\begin{verbatim}
module Data.Int (
    Int, Int8, Int16, Int32, Int64
  ) where\end{verbatim}}
\haddockendheader

This module provides signed integer types of unspecified width (\haddockid{Int}) and
 fixed widths (\haddockid{Int8}, \haddockid{Int16}, \haddockid{Int32} and \haddockid{Int64}). All arithmetic is
 performed modulo 2{\char '136}n, where n is the number of bits in the type.\par
For coercing between any two integer types, use \haddocktt{fromIntegral}. Coercing word
 types (see \haddockid{Word}) to and from integer types preserves representation,
 not sign.\par
The rules that hold for \haddocktt{Enum} instances over a bounded type such as \haddockid{Int}
 (see the section of the Haskell language report dealing with arithmetic
 sequences) also hold for the \haddocktt{Enum} instances over the various Int types
 defined here.\par
Right and left shifts by amounts greater than or equal to the width of the
 type result in either zero or -1, depending on the sign of the value being
 shifted. This is contrary to the behaviour in C, which is undefined; a common
 interpretation is to truncate the shift count to the width of the type, for
 example 1 << 32 == 1 in some C implementations.\par
\begin{haddockdesc}
\item[\begin{tabular}{@{}l}
data Int
\end{tabular}]
{\haddockbegindoc
A fixed-precision integer type with at least the range \haddocktt{{\char 91}-2{\char '136}29 .. 2{\char '136}29-1{\char 93}}.
 The exact range for a given implementation can be determined by using
 \haddockid{minBound} and \haddockid{maxBound} from the \haddockid{Bounded} class.\par}
\end{haddockdesc}
